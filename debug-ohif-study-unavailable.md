# Debug Session: ohif-study-unavailable

Status: [OPEN]

## Symptom
OHIF displays: "One or more of the requested studies are not available at this time. Return to the study list to select a different study to view."

## Hypotheses
1. The StudyInstanceUID passed to OHIF differs from the UID generated by Flask.
2. The DICOMWeb metadata response does not match OHIF's expected Study/Series structure.
3. The generated DICOM files are missing or mapped to the wrong directory.
4. OHIF is opened before the DICOMWeb study is ready.

## Evidence
- OHIF reported `Route /notfoundstudy` and `Invalid study URL` before a usable study was opened.
- OHIF source shows data-source routes are built as `/<mode>/<dataSourceName>`.
- The previous URL used `/viewer?...&datasources=local5000`, which did not select the explicit `local5000` route for this build.
- Flask exposes the local DICOMWeb source under `http://localhost:5000/dicomweb`.

## Root cause
The embedded OHIF URL used the wrong route form for the checked-in OHIF build. It did not reliably activate the `local5000` data source, so the StudyInstanceUID was parsed in the wrong route context and OHIF redirected to `/notfoundstudy`.

## Fix
- Use `/viewer/local5000?StudyInstanceUIDs=...` when opening an uploaded study.
- Set `defaultDataSourceName` to `local5000` in the default OHIF config.

## Verification needed
Restart OHIF so the public config is reloaded, upload the test CT again, and confirm that the viewer opens the image instead of `/notfoundstudy`.
